# Experiment 0042 — exact prepacked DeepSeek mHC projection

Status: **promoted as the default decode optimization; `--no-prepack-mhc` opts out.**

## Contract

- Hypothesis: the 24 independent FP64-ordered rows in each DeepSeek mHC
  projection can be evaluated four at a time if the immutable FP32 projection
  is repacked once at admission. Four AVX2 lanes then preserve each row's
  original column order without changing any value or using FMA.
- Primary metric: median single-stream decode steps/s over three interleaved
  repetitions at the production chat operating point. Require at least 1.05x,
  above the observed approximately 5% run variance.
- Correctness gate: byte-identical operation/layer hashes, logits, generated
  tokens and routes in a short diagnostic; equal generated tokens and route
  traces in every performance arm; exact execution or explicit failure.
- Memory ceiling: 216 GiB host and 0.95 of each GPU. The candidate must account
  for its additional host allocation and keep VRAM unchanged.
- Rollback: any exactness failure, decode checkpoint read, unaccounted memory,
  or median speedup below 1.05x.

DS4 commit `45a9dcb` was the useful prompt: treat HC rows as a batch and keep
the HC/norm path together instead of dispatching each row independently. Its
ROCm kernel and GGUF representation are not used here. Strata instead applies
the row-batching idea to its exact CPU projection, with the original FP32
weights and FP64 accumulation order. No GLM path or quantization change is
involved.

## Bottleneck and target term

The cost model was instantiated first at this exact operating point: 18 prompt
tokens, 152 generated tokens (151 timed decode steps), three GPUs, 216 GiB host,
0.95 VRAM fraction, FlashAttention, pinned resident arena, scalar KV. The prior
pure-host-residue measurement put host CPU at 104--142 ms/step, PCIe demand at
about 63 ms/step, and the maximum GPU kernel path at about 41 ms/step. Host CPU
was `argmax_r`; the direct row-interleaving experiment in commit `f3ffa91`
reduced mHC by only 11.6 ms/step and was rejected before runtime integration.

The frozen reference in this experiment measured:

| serial phase/resource term | median ms/step |
|---|---:|
| whole decode step | 249.105 |
| MoE total, including demand | 118.835 |
| attention total | 82.960 |
| pinned PCIe demand wait | 62.810 |
| **mHC pre, target host-CPU term** | **37.945** |
| maximum CUDA kernel path | 41.075 |

The phases overlap in resource attribution, so they must not be summed as
independent `W_r/B_r` terms. The decision is still unambiguous: mHC belongs to
the current host-CPU bottleneck, and the mechanism reduces that term without
adding PCIe or GPU work.

Each step reads the same 135,266,304 projection bytes and performs the same
33,816,576 ordered dot-product elements. Only the host layout and lane-level
parallelism change. Other-resource signs:

- host RAM: +135,266,304 bytes admitted, plus one-time packing work;
- host projection bytes per step: unchanged;
- PCIe weight and activation bytes: unchanged;
- GPU calls, kernels, VRAM, routing, precision, expert count and top-k:
  unchanged;
- NVMe: still zero during decode.

## Cheapest falsifying measurement

`strata-mhc-prepack-probe` reproduces all 86 production mHC projections per
step, their `[24, 16384]` shape, and a 135 MB rotating working set. Seven
alternating repetitions first require byte equality against
`dsv4_mhc_pre_f32`.

```text
scalar_ns_per_call       392290
prepacked_ns_per_call    179399
speedup                  2.1867x
projected_ms_per_step    18.3087
```

The predeclared gate was 15 ms/step. This passed before any end-to-end run.
The rejected cheaper alternative was direct row interleaving, which reached
only 11.6 ms/step in the same production-shaped probe.

## Implementation

The exact prepacked path is default-on; `--no-prepack-mhc` opts out. During
warm-up it transposes the 86 immutable
`[24, 16384]` projections into four-row blocks. The AVX2 kernel holds four
independent FP64 accumulators; every lane visits columns in the scalar oracle's
order and executes separate multiply and add instructions. Unsupported CPUs or
missing packed tensors fail explicitly—there is no hidden fallback after the
option is requested.

Admission adds the exact 135,266,304 bytes to host workspace. Runtime metrics
publish the planned bytes and packed call count.

## Commands and budget

```bash
./build/strata-mhc-prepack-probe

RESULT_DIR=results/deepseek-v4-mhc-prepack-correctness \
MAX_NEW_TOKENS=2 REPETITIONS=1 TRACE=1 MIN_SPEEDUP=0 \
scripts/run_deepseek_v4_mhc_prepack_ab.sh

scripts/run_deepseek_v4_mhc_prepack_ab.sh
```

The correctness pair took about two minutes. The performance matrix budget was
about two minutes per arm and 12 minutes total; measured fixed setup plus
prefill was 51.5 s against a 37.6 s reference decode window, a 1.37 ratio. The
18-token prompt was kept because decode is under test; a longer prompt would
only increase unrelated prefill.

Both jobs ran in named tmux sessions. Evidence is under ignored deterministic
paths `results/deepseek-v4-mhc-prepack-correctness/` and
`results/deepseek-v4-mhc-prepack-ab/`.

## Correctness result

The two-step full-model diagnostic passed byte-identical generated tokens,
routes, logits, layer hashes and operation hashes. It exercised all 86 packed
calls per timed step, read zero checkpoint bytes during decode, and measured
36.52 versus 16.44 mHC ms/step. The unit fixture also compares the scalar and
prepacked operation's reduced output and every mix vector exactly before the
candidate is accepted.

## Performance result

Every run is reported below. Arms were interleaved reference/candidate,
candidate/reference, reference/candidate.

| 1 | reference | 4.0158 | 37.601 | 38.524 | 62.810 |
| 1 | candidate | 4.4694 | 33.785 | 16.584 | 62.954 |
| 2 | reference | 4.0144 | 37.615 | 37.727 | 62.442 |
| 2 | candidate | 4.4203 | 34.160 | 16.814 | 62.148 |

Median decode speedup is **1.1134x**. The slowest candidate run is still 10.1%
faster than the fastest reference run, so the ranges do not overlap. The
mechanism saves 21.36 mHC ms/step and 25.36 whole-step ms; the additional
approximately 4 ms is movement in untouched phases and is not credited to the
mechanism.

The resource cross-check supports the causal claim:

| activation H2D bytes, every run | 1,909,035,008 | 1,909,035,008 |

RSS rises by 135,442,432 bytes, within 176 KiB of the admitted allocation.
Required host bytes rise by exactly 135,266,304, from 150,988,061,020 to
151,123,327,324, below the 216 GiB ceiling. All six runs generated the same
tokens and identical 7,268-line route traces. Decode checkpoint reads are zero.

Median prefill also falls from 6.804 to 6.396 s, consistent with the same exact
mHC operation, but prefill was not the primary metric and is not part of the
acceptance claim.

## Decision

Promote the implementation as the default DeepSeek optimization. It clears the
5% materiality gate by more than twofold, reduces the intended host-CPU term,
and leaves every non-host work counter unchanged. Users on unsupported CPUs or
systems where the extra host allocation is undesirable can pass
`--no-prepack-mhc`.
